## Decisions already made (2026-09-19, user sign-off)

- Three separate routes: `/login` (buyer, phone OTP), `/developers/login` and `/admin/login` (email + password). The word "staff" is not used in the UI or in route names.
- A user's role is the presence of a row in `developer_users` or `admin_users`. A developer account signing in at `/admin/login` (or the reverse) is rejected with the same generic error as a bad password — the screen does not reveal which role an email has.
- Developers are invited by an admin (separate step in the parent tasklist); there is no public developer or admin sign-up. Public email/password sign-up must therefore be disabled in `src/lib/auth.ts`, not merely unlinked.
- Design: follow the Soft Daylight tokens already in `globals.css`. The three screens share one layout so they read as one product, not three bolted-on forms.

## Open items (surface, do not guess)

- **First-admin bootstrap.** With sign-up disabled, the first admin needs a path. Proposed: a one-off maintainer script that creates the `users` + `admin_users` rows (identity only — it writes no live catalog table, so the one-write-path rule is not touched). Needs sign-off.
- **Invite set-password link** belongs to the developer-onboarding step, not this one; this tasklist only builds the sign-in screens and the `/developers/set-password` landing they will hand off to is deferred.
- **SMS provider** is still unchosen (`sendOTP` logs in dev, throws in production). The OTP screen is built against Better Auth's `phoneNumber` plugin; production OTP delivery stays blocked on that decision.
